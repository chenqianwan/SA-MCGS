### 7.1 已确认的技术事实，避免从零重复调查

- `search()` 先完成 rollout 循环，再经 `_build_result` 生成累计证据摘要、调用最终 core selector。生产路径不在每轮把 prefix core 反馈进搜索。
- core priority 实际为 `s_T(v) = e_T(v) + 0.24 b_T(v) + 0.16·1[v∈O_T]`。`e_T` 为组件归一化证据通道的均值；Root 排名另按节点平均风险，不是该 core score。
- 实际 core 选择是 protected-pair seeding、固定优先级扫描、分数／间隙停止、容量内 pair closure；原稿精确 argmax／超 cap 后删点不能直接当作实现。
- OC 来自节点风险历史的三条件两票规则：标准化均值大于 1.5、平均经验 percentile 大于 0.8、超过 pooled median 的比例大于 0.8；并有 warm-up、最少观察数等门槛。不是 LLM 返回的 `oc_candidate`，也不是原稿的关系分位数规则。
- pair memory 累计支持次数、explicit reports、关系理由和 ledger；不采用原稿 EMA。无序 pair key 与有向图边的搜索统计是两回事。
- 普通窗口按邻接前沿扩展，定期 endpoint probe 可包含桥接路径，最后仍受 `w=4` cap；不是完整半径球。缓存使 rollout slots 与真实请求数不同。
- 算法 4 改写时，关系循环内仅更新 pair；节点 local-subgraph／repair-entry 计数按 evaluation entry 聚合，不能放入逐关系循环重复累计。
- 公式 4 的加性噪声可以与实现代数等效，不能笼统说整条 UCB 式错。公式 5 需局部说明 frontier bonus；参数表 1.55 对应 critical-pair score，1.35 对应 semantic strength。详见清单 7.5–7.6。
