Figure 1: Evidence-guided search and terminal core selection
a, A record graph is decomposed into strongly connected components. b, Each rollout selects a bounded window using accumulated evidence. A local evaluator returns node scores y_t(v), relation evidence z_t(u,v), and a local risk subgraph h_t; eligible cached evaluations can be reused. Memory retains normalized node evidence e_t(v), risk-score histories Y_t(v), unordered pair support m_t(p), relation reasons, and a critical-pair ledger. The program computes persistent online conflict (OC) flags from eligible histories using two-of-three tests. Accumulated memory guides subsequent window selection. c, After budget T, the final core is constructed under B(S) by pair seeding, priority scanning with stopping rules, and supported-pair closure. Its priority uses normalized evidence, the strongest qualifying pair score, and OC flags. R_T(v) contains qualifying observed pairs involving v; b_T(v)=0 if it is empty. Risk ranking is a separate readout based on mean observed risk qbar_T(v). Gray arrows show original directed edges; rust dashed lines show unordered observed pairs. The illustrative A–D pair has no original edge in either direction. No empirical result is encoded.

Figure 2: Evidence acquisition on a common cyclic component
The same record identities and directed topology underlie all four views. a, Full-SCC (one-shot) evaluates the complete component in one request and directly returns a subgraph and ranking. b, Local Evidence Aggregation (LEA) evaluates fixed, potentially overlapping, node-anchored windows and aggregates mean risk and evidence counts. Two windows are illustrated; the ellipsis represents additional anchors. LEA uses the resulting membership scores to select its fixed-capacity subgraph and mean risk to rank nodes. c, TreeMCTS attaches statistics Q_pi and N_pi to path-prefix states s_pi; repeated physical records therefore appear at multiple tree positions. d, SA-MCGS updates shared evidence memory M_t using local evaluation output Ecal_t, feeds memory back into adaptive window selection, and constructs the final core after T. Select, Eval, Update, Core, and Rank are schematic operation names; the component S is an implicit argument of Select. Blue nodes identify anchors or revisited records. Rust dashed lines indicate observed pair evidence, which need not coincide with a directed graph edge. All diagrams are illustrative, with no measured performance comparison.

复现
安装 requirements.txt 中的绘图依赖后，运行 python draw_figures.py。
draw_figures.py 是可单独运行的完整源文件。figure_style.py、draw_framework.py、draw_comparison.py 是便于分图继续修改的模块源。若修改模块源，应同步重建完整源文件。

内容与质量检查
两图使用同一 A–E 拓扑。局部窗口画出其所有内部原图边；路径展开中的每次转移均属于原图。LEA 示例窗口与固定节点顺序一致。所有返核箭头都位于搜索结束后，core 不参与下一轮搜索反馈。没有实验数据、模拟统计或性能优劣暗示。
